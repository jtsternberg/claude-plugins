# Handoff Plugin Upgrade (v2.1.0)

## Context

The handoff plugin (write/pickup handoff docs between sessions) works but every step
depends on a human remembering: docs only get written if you run `/handoff`, only get
found if the next session looks, and litter the repo afterward. Pickup agents also
wrongly treat the doc as a living document. This upgrade makes the loop mechanical
(hooks), the content trustworthy (SHA anchoring, transcript pointer), the lifecycle
clean (read-once, delete/close on completion, git-exclude), and adds a beads backend
as progressive enhancement.

Decisions made with JT:
- Same-machine assumption is safe (session IDs/transcripts are machine-local).
  Cross-machine/durable handoff = deferred beads task, not built now.
- Beads is the *preferred* backend when available; `.md` file is the universal
  fallback. Progressive disclosure: lean SKILL.md + conditional `references/` files
  (model: `plugins/fable/skills/fable-mode/SKILL.md`).
- No Stop-hook nudge (fires every turn = nag). No PreCompact (undocumented
  capabilities). Post-compact nudge via SessionStart `compact` matcher instead.
- The pickup banner at the top of the doc is the primary cold-start path and stays.
- Minimal ceremony; version bump once at the end (2.0.0 → 2.1.0).

## Constraints discovered

- **AM Skills publish transform** (`.amskills.json`): handoff + pickup-handoff are
  published standalone with a sed rewrite `/handoff:pickup-handoff` → `/pickup-handoff`.
  Keep that exact string intact in SKILL.md text. Skills must degrade gracefully when
  installed standalone (no plugin hooks, no `${CLAUDE_PLUGIN_ROOT}` scripts).
- Hook facts (docs-verified): plugin ships `hooks/hooks.json` at plugin root;
  `${CLAUDE_PLUGIN_ROOT}` resolves in commands; SessionStart matchers include
  `startup|resume|clear|compact`; SessionStart stdout is injected into context;
  hook stdin JSON has `session_id`, `cwd`, `hook_event_name` (`transcript_path`
  implied but not guaranteed — handle absence).
- No existing hooks in this repo; external template: superpowers cache
  `~/.claude/plugins/cache/claude-plugins-official/superpowers/6.1.1/hooks/`.
- Beads detection idiom (new, but consistent with `yt-dlp` skill preflight):
  `command -v bd >/dev/null 2>&1 && [ -d .beads ]`.

## Work items

### 1. `skills/handoff/SKILL.md` rewrite (lean core)

- Backend preflight: bd installed AND `.beads/` in repo → read `references/beads.md`;
  else → read `references/files.md`. Shared content contract stays in SKILL.md:
  - Sections: Goal, Current Progress, Files Changed, What Worked, What Didn't Work,
    Next Steps (existing), plus new **Anchor** (HEAD SHA + branch + ISO timestamp)
    and **Session** (session ID + transcript JSONL path when determinable — read
    from the hook-written cache, see item 4; omit gracefully if absent).
  - Every run ends with a "To resume" block: primary = run `/handoff:pickup-handoff`;
    fallback = backend-specific (`Read <abs path> and continue where we left off`
    for files; `bd show <issue-id>` for beads).
- `references/files.md`: current filename logic (branch/descriptive suffix), pickup
  banner at top, **add `HANDOFF*.md` to `.git/info/exclude`** (idempotent), update
  vs create logic.
- `references/beads.md`: create/update a bd issue titled `Handoff: <work-name>`
  (`-t task`, description = full handoff content, `--json`); reuse existing open
  handoff issue for same work rather than creating duplicates; resume block states
  issue ID explicitly.

### 2. `skills/pickup-handoff/SKILL.md` rewrite

- Find handoff: named file > branch/descriptive `HANDOFF*.md` glob > open
  `Handoff: *` bd issues (when bd present). Multiple candidates → list and ask.
- **Drift reconciliation**: use the Anchor SHA — `git log --oneline <sha>..HEAD`,
  `git status` — report "N commits since handoff was written; here's what changed"
  reconciled against the doc's claims.
- **Read-once directive (blunt)**: the handoff is a boot artifact, NOT a living
  document. Never update it after reading. When the work completes: delete the file
  / `bd close` the issue (tell the user you did).
- **Stale sweep**: list *other* `HANDOFF*.md` files with mechanical facts only
  (file age, anchor-SHA drift, branch merged/deleted) and flag obvious corpses for
  deletion. No subagents for this — cheap git commands suffice.
- **Transcript escape hatch**: if the doc is thin on a detail, grep the Session
  transcript JSONL for it. Deluxe tier (conditional, one line + reference): if the
  hotline plugin is installed, offer to dial a fresh agent seeded with that
  transcript for interactive questioning.

### 3. `hooks/hooks.json` + `scripts/`

- `SessionStart` matcher `startup|resume` → `scripts/session-start.sh`:
  (a) cache stdin's `session_id`/`transcript_path` (keyed for later skill lookup,
  e.g. `/tmp/claude-handoff/<claude-ancestor-pid>` — ancestry-walk pattern borrowed
  from hotline's `session-fingerprint.sh`); (b) scan cwd for `HANDOFF*.md` and (if
  bd) open `Handoff:` issues; if found, print one line per handoff with facts
  (name, age, drift count) + suggest `/handoff:pickup-handoff`. Silent when clean.
  Fast (~2s timeout), always `|| true`.
- `SessionStart` matcher `compact` → `scripts/post-compact-nudge.sh`: refresh the
  session cache; print a one-line nudge that context was just compacted and, if
  mid-task, `/handoff:handoff` will bank fresh context.
- Scripts must be pure-bash/POSIX-safe, no deps, degrade silently on any failure.

### 4. Session cache contract (shared)

Hook writes `/tmp/claude-handoff/<pid>.json` (`session_id`, `transcript_path`,
`cwd`). Skill-side read: walk process ancestry to find the claude PID (hotline's
proven approach) and read the cache. Cache miss (standalone AM Skills install,
hook disabled) → skill omits the Session section without complaint.
