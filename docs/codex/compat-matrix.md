## Findings

- The current source scan finds **28** affected `SKILL.md` files, not the expected 32: **26** contain `CLAUDE_SKILL_DIR` and **2** contain `${CLAUDE_PLUGIN_ROOT}` in a skill body. This refines the earlier document's 28/4 split and its 32-file blast-radius statement. The two plugin-root skill sites are `sessions-catch-up` and `sessions-fork`; the other `session-tools` skill uses `CLAUDE_SKILL_DIR`.
- This is a static source audit, not a re-run of the variable probe. The incompatibility classification remains conditional on the 0.144.6 behavior continuing in the current 0.145.0 build.
- No referenced bundled target was absent from its plugin directory, except the hard-coded legacy path in `git-tree` noted above. The `handoff` hook configuration is not a failure: `${CLAUDE_PLUGIN_ROOT}` is used in `hooks/hooks.json`, where the probe says Codex supplies it.
- Assuming the probe behavior remains true, `gws`, `session-tools`, `localwp-shell`, `research-tools`, and `slack` are effectively non-functional for their advertised Codex skill workflows: every skill in each depends on an unset location variable. `fable` also has both skill documents affected, though its prose guidance remains readable after the setup-script call fails.
